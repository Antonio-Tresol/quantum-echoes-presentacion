Concepto1 / 7

La idea en una línea

Un plataformero de precisión donde cada intento queda grabado, y tu yo del pasado vuelve como fantasma para resolver lo que una sola persona no puede.

El pilar de diseño

Lo llamamos "ajedrez temporal": cada run es una jugada estratégica. Decides qué hacer, qué guardar y qué grabar, sabiendo que tu yo futuro va a aprovechar esas decisiones.

Referencias: Metroidvania (Hollow Knight), feel de precisión (Celeste), eco temporal (Super Time Force), bucle (Majora's Mask).
Concepto1 / 7

El bucle temporal

  • Cada nivel tiene un temporizador. Cuando se acaba, el run termina.
  • El run también termina al perder los 3 corazones o de forma voluntaria.
  • Al terminar, decides si grabar ese run como tu nuevo fantasma.
  • Nuevo run: el mundo se reinicia, los enemigos vuelven frescos, pero la caja temporal persiste y el fantasma reproduce el run grabado.

Core loop

Empieza run, el fantasma reproduce su grabación, navegas, recoges e interactúas, guardas en la caja temporal, el run termina, grabas o no, y repites hasta completar el nivel.

Arquitectura2 / 7

El stack y las decisiones de base

Unity 6.3.11f1

Motor 2D, física Rigidbody2D, Tilemaps.

New Input System

Handlers por callback, sin polling. El input emite eventos, los componentes se suscriben.

GameManager

Coordinador central. Singleton que orquesta el ciclo de run y guarda la grabación.

No hay un PlayerController monolítico

El jugador es un prefab compuesto de varios MonoBehaviour, cada uno con una sola responsabilidad. Añadir una habilidad es siempre la misma operación: un componente que se cuelga del prefab.

Arquitectura2 / 7

Tres roles: Source, Writer, Observer

Source

Produce información, no cambia el mundo.

PlayerInputSource, GroundCheck

Writer

Cambia el estado del mundo (Rigidbody, eventos).

HorizontalMovement (eje x), JumpAbility (eje y)

Observer

Lee y reacciona, no cambia estado.

Loggers, audio, VFX

Reglas que evitan dolor

  • Un Writer por eje y por tick. Si dos quieren el mismo eje, se decide quién manda por gating.
  • Suscribir en OnEnable, desuscribir en OnDisable. Espejo exacto, sin handlers fantasma.
  • Lógica de algoritmo en helpers puros de C# (sin Unity), probados en EditMode.

Jugador4 / 7

Game feel: los tres clásicos del salto

Coyote time

Permite saltar un instante después de salir de la plataforma. Perdona el frame perdido.

Jump buffer

Si presionas salto justo antes de aterrizar, se guarda y salta al tocar el suelo.

Salto variable

Mantener el botón sostiene la altura un poco más. Tap corto, hold largo.

// helper puro de C#, sin Unity, probado en EditMode
public class CoyoteTimer {
    public void Refresh() { remaining = window; }
    public void Tick(float dt) { remaining -= dt; }
    public bool CanJump => remaining > 0f;
}
Reciben dt por parámetro, así no dependen de Time.fixedDeltaTime y se prueban mucho más rápido.
Jugador4 / 7

Wall Grip: la más compleja del jugador

  • Se agarra si estás en el aire, hay pared al lado, y empujas hacia la pared (detección por OverlapBox).
  • Sostiene 1 segundo, o sueltas antes empujando al lado contrario.
  • Salto durante el agarre dispara el wall jump: impulso hacia afuera y arriba.
  • El wall jump resetea el uso, así se encadenan saltos entre paredes.
La sutileza: tras el wall jump hay un lockout de input de ~150ms. Sin él, HorizontalMovement corrige el impulso al instante y el arco se siente plano.
if (dash.IsDashing) return;
if (wallGrip.IsGripping) return;
if (wallGrip.IsInWallJumpLock) return;
// HorizontalMovement cede el eje x

El algoritmo: una FSM, no pathfinding

Cada enemigo es una máquina de estados finita. En cada frame, según el estado actual, se ejecuta el tick correspondiente.

Patrol
→
Alert
→
Chase
→
Attack
→
Hit
→
Dead
switch (State) {
    case EnemyState.Patrol: TickPatrol(dt); break;
    case EnemyState.Chase:  TickChase(dt);  break;
    case EnemyState.Attack: TickAttack(dt); break;
    // Alert, Hit, Dead...
}
Enemigos5 / 7

Detección y daño

Detección por rango

  • detectionRange: dentro de él, Patrol pasa a Alert y luego Chase.
  • attackRange: dentro de él, Chase pasa a Attack.
  • Cálculo simple de distancia al objetivo cada frame.

Pipeline de daño

  • IDamageable: interfaz común para todo lo que recibe golpes.
  • Al recibir daño: resta vida, entra a Hit (stun), aplica knockback direccional.
  • A 0 de vida: pasa a Dead.
Regla del GDD: los enemigos respawnean frescos cada run. El eco nunca altera el estado de los enemigos entre runs.
Enemigos5 / 7

El Caballero Oscuro: escudo direccional

Hereda de la misma base (BossBase : EnemyBase) pero añade dos mecánicas:

  • Escudo frontal: bloquea ataques del lado que el jefe encara. El facing se calcula en vivo, así sobrevive a teleports.
  • Daño por contacto: tocar el cuerpo cuesta vida (estilo Hollow Knight).
bool ShouldBlockDamage(Vector2 src) {
    float dx = src.x - position.x;
    return Mathf.Sign(dx) == ComputeFacing();
}

La estrategia invertida

No le puedes pegar de frente. La solución: tú haces de cebo manteniéndote al frente, mientras tu fantasma lo golpea por la espalda. El jefe ignora al fantasma.

Aquí el eco deja de ser una herramienta de puzzle y se vuelve una de combate.

El sistema de Eco

La mecánica más compleja, a fondo.

Deep dive: Eco6 / 7

El corazón del juego

"En el siguiente run, un fantasma replica esa grabación exacta."

El jugador graba un run. En el siguiente, un fantasma reproduce ese run: movimiento, interacciones con el mundo y ataques. Sus interacciones afectan el mundo en tiempo real.

  • Máximo un fantasma activo a la vez.
  • El fantasma es invulnerable.
  • Sus ataques impactan enemigos solo si coinciden en posición y tiempo.
Deep dive: Eco6 / 7

Paso 1: grabación

Cada FixedUpdate, el PlayerRecorder guarda un snapshot del estado del jugador.

new PlayerSnapshot {
    position, velocity,
    moveInput, jumpHeld,
    jumpStarted, attackStarted,
};
Por qué FixedUpdate: ahí corre la física. Grabar al mismo ritmo garantiza que el fantasma se reproduzca igual en cualquier máquina.

El detalle difícil

Los eventos de un solo frame (un ataque, un salto) se marcan y se limpian cada tick. Tienen que sobrevivir el viaje completo: evento, captura en el snapshot, almacenamiento, reproducción, y dispararse exactamente una vez.

void NotifyAttackStarted() =>
    attackStartedThisFrame = true;
// se captura en el próximo snapshot
Deep dive: Eco6 / 7

Paso 2: reproducción

El fantasma usa un Rigidbody2D Kinematic: no simula física, escribe la posición y velocidad grabadas directamente.

PlayerSnapshot snap = buffer[frameIndex];
body.position = snap.position;
body.linearVelocity = snap.velocity;
if (snap.attackStarted)
    attack.TryAttack(facing);
frameIndex++;
Punto fino para preguntas: no re-simulamos los inputs, reproducimos el estado grabado. Así esquivamos cualquier divergencia de física entre máquinas o runs. Es replay de estado, no re-simulación.

Al acabarse el buffer, el fantasma frena y avisa al spawner para destruirse, una sola vez.

Deep dive: Eco6 / 7

Paso 3: el ciclo run N a fantasma N+1

Run N
PlayerRecorder graba snapshots
→
Fin del run
GameManager guarda la grabación
→
Run N+1
GhostSpawner instancia y reproduce

El GameManager es el coordinador: emite OnRunStart y OnRunEnd, guarda el arreglo de snapshots del run que termino, y en el siguiente run el spawner crea el fantasma con esa grabación.

Tres piezas, una responsabilidad cada una: el recorder graba, el GameManager guarda, el spawner reproduce.
Deep dive: Eco6 / 7

El giro: reencarnación y el orden de ejecución

La reencarnación intercambia tu posición con la del fantasma, y lo consume. En el siguiente run, la grabación incluye ese teletransporte.

Para eso, el swap se hace dentro del callback del Input, que corre en Update, no en FixedUpdate.

Si escribiéramos la posición en FixedUpdate, Unity no garantiza el orden entre scripts. Si el recorder corre primero, ese snapshot llevaría la posición vieja y la grabación se rompe por un frame. El callback de Input siempre corre antes del próximo FixedUpdate del recorder.

Es el problema inverso al recorder: una mecánica elige FixedUpdate a propósito, la otra elige Update a propósito, ambas por el orden de ejecución.

Deep dive: Eco6 / 7

Por qué vale la pena: todo se junta

El sistema de eco no es una curiosidad técnica: es lo que hace posible la pelea del Caballero.

  • Run 1: grabas un recorrido que ataca donde estará el jefe.
  • Run 2: tu fantasma reproduce esos ataques por la espalda, mientras tú haces de cebo de frente.
  • El escudo frontal más el daño por contacto fuerzan esa cooperación.
